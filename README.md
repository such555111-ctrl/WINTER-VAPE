# VAPE WINTER — Telegram Mini App

Витрина **VAPE WINTER · VAPE STORE** (жидкости, расходники, снюс; 21+) в виде Telegram-бота с мини-приложением:
каталог, избранное, корзина, промокоды, оформление заказа, профиль с историей заказов и админ-панель.
Заказ уходит менеджеру (@vapewinter_manager — замените через `SHOP_CONTACT`), онлайн-оплата не подключена.

## Состав
```
main.py           — Flask-сервер (все данные — в Neon): мини-апп, Telegram-бот (webhook), API админки
index.html        — интерфейс мини-приложения (21+ гейт, hero, каталог, корзина, заказ)
admin.html        — админ-панель (товары, заказы, вопросы, промокоды)
products.json     — каталог магазина (необязательно: при первом запуске пустая база заполняется из него; иначе наполняйте через /admin)
brand/            — logo.svg (светлый логотип для тёмного фона), logo-dark.svg (для светлого), mark.svg (значок-снежинка),
                    favicon.svg, avatar.svg / avatar.png (аватарка бота 640×640); отдаются по /brand/<файл>
requirements.txt, Procfile, render.yaml — запуск на Render
```

## Районы

Каталог делится по районам. Пока в админке не создан ни один район, магазин работает как раньше (общий каталог, район не спрашивается).
После создания первого района покупатель при входе выбирает район и видит только доступный там ассортимент; в шапке есть
кнопка **«Сменить район»**. Выбор запоминается на устройстве (`vw_district`).

**Админка → вкладка «Районы»:** добавить район, переименовать, временно отключить/включить, удалить.
**Карточка товара → «Районы, где продаётся товар»:** «Все районы» или один/несколько районов. Старые товары без привязки считаются товарами «для всех районов».

**Что происходит с данными**
| Ситуация | Поведение |
| --- | --- |
| Район отключён | Скрыт из выбора, каталог и оформление в него отвечают 410. Привязки товаров сохраняются — при включении всё возвращается. Открытые заказы остаются. |
| Клиент в приложении, а район отключили/удалили | При следующем обновлении каталога или оформлении заказа открывается выбор района; корзина сохраняется, недоступные в новом районе товары убираются с предупреждением. |
| Район удалён | Привязка снимается с товаров; опционально товары, привязанные только к нему, переносятся в другой район. Товар без единого района скрыт от покупателей (в админке помечен «⚠ не привязан») и появится после назначения района. |
| Заказы | В заказе хранятся `district_id` и `district_name` на момент заказа. После удаления района заказ остаётся, его можно принять/отклонить; в админке видна пометка «район удалён/отключён». При переименовании название обновляется только у необработанных заказов. |
| Оформление заказа | Сервер проверяет район (активен ли) и что каждый товар продаётся в нём; иначе 410/409 с понятным текстом, заказ не создаётся. Остатки, промокоды и оплата работают как прежде (остаток общий на товар, не по районам). |

API: `GET /api/districts` (активные районы), `GET /products.json?district=<id>`, `POST /api/order` (поле `district_id`),
`GET/POST /api/admin/districts`, `PUT/DELETE /api/admin/districts/<id>` (`DELETE ?move_to=<id>` — перенос товаров).
Администратору в Telegram приходит строка «📍 Район: …» в уведомлении о заказе; клиенту — в подтверждении.

## Запуск (Render)
1. @BotFather → `/newbot`, затем `/setuserpic` → `brand/avatar.png` (логотип Vape Winter).
2. Загрузите файлы в корень GitHub-репозитория, на Render создайте Web Service.
   Build: `pip install -r requirements.txt`, Start: `gunicorn main:app --bind 0.0.0.0:$PORT`.
3. Переменные окружения: `BOT_TOKEN`, `ADMIN_PASSWORD`, `ADMIN_CHAT_ID` (ваш Telegram ID, можно несколько через запятую),
   `SHOP_CONTACT` (по умолчанию `vapewinter_manager`), `WEBHOOK_URL` (необязательно),
4. `/start` в боте → «❄️ Открыть Vape Winter». Админка: `https://ваш-адрес.onrender.com/admin`.

## Что заполнить после запуска
- Фото товаров, реальные вкусы/цвета и описания — через `/admin` (сейчас у позиций «Вкус / цвет — по согласованию» и цветные плашки).
- Бейджи («Хит», «Скидка» и т.д.) — в админке.
- Номера заказов имеют вид `VW-12`.

> Проверьте требования законодательства вашего региона к продаже и дистанционной торговле никотиносодержащей продукцией.

## Хранение данных (Neon)
Всё хранится в PostgreSQL на Neon — рестарты и деплои на Render ничего не стирают, Persistent Disk не нужен:

| Таблица | Что лежит |
| --- | --- |
| `products` | товары (включая остатки, бейджи, ссылки на фото) |
| `orders` | заказы и переписка с покупателем |
| `questions` | вопросы по товарам |
| `promos` | промокоды и счётчики использования |
| `images` | фото товаров (загружаются через админку, сжимаются до 1600 px WebP, отдаются по `/uploads/<имя>`) |
| `meta` | служебный флаг первичного переноса |

Нужна одна переменная `DATABASE_URL` (строка подключения Neon, с `?sslmode=require`). Таблицы создаются автоматически.
При первом запуске пустая база заполняется из `products.json` (и `orders.json`, `questions.json`, `promos.json`,
папки `uploads/`, если они есть) — один раз; дальше источник правды — база, а `products.json` в репозитории можно не трогать.
Фото, которые больше не привязаны ни к одному товару, удаляются из базы автоматически.

## Анимации
- Интерфейс: лёгкий дым на фоне, бегущая лента, появление hero-арта, жёсткие «сдвиговые» тени кнопок.
- Для пользователей с включённым «уменьшить движение» в системе все анимации отключаются автоматически.

## Заказ: через менеджера
При оформлении покупатель не вводит имя, телефон, адрес и время. Есть два пути:
- **«Написать менеджеру»** — заказ записывается в систему, открывается чат с менеджером (`SHOP_CONTACT`) с готовым текстом заказа;
- **«Оставить юзернейм»** — клиент указывает свой Telegram-@username, менеджер пишет первым (админам уходит пометка «Менеджер должен написать клиенту первым»).
Баллы, кешбэк, отзывы, доставка и самовывоз из мини-приложения убраны.

## Подкатегории
У товара есть необязательное поле `subcategory` (бренд): например `Поды › Vaporesso › Xros 6`.
В каталоге под категориями появляется вторая строка фильтров с количеством товаров; товары без подкатегории
попадают в «Другие». Поле заполняется в админке («Подкатегория / бренд»), подсказки берутся из уже созданных.

## Замена каталога
При первом запуске после деплоя `replace_catalog_once()` один раз удаляет все прежние товары из базы и загружает товары из `products.json` (флаг `catalog_v2` в `meta`). Заказы и промокоды не трогаются. Id новых товаров начинаются с 10000.

## Остатки товара
В админке (карточка товара → «Остаток на складе, шт.») и прямо в списке товаров (кнопки «−» / «+» и поле ввода) можно указывать количество.
- Пусто — учёт не ведётся, товар без ограничений (так по умолчанию).
- В каталоге у карточки появляется плашка: «В наличии: N шт.» (больше 10), «Осталось N шт.» (4–10), «Последние N шт.» / «Остался 1 шт.» (1–3), «Нет в наличии» (0).
  Распроданные товары уходят в конец ленты, блёкнут, их нельзя добавить в корзину.
- В карточке товара — шкала остатка; в корзину нельзя положить больше, чем есть на складе.
- При оформлении заказа сервер проверяет остатки и списывает их; отмена заказа (клиентом или в админке) возвращает товар на склад,
  возобновление отменённого заказа списывает снова. Остатки в мини-приложении обновляются при возврате в приложение и после заказа.
- Остатки хранятся в таблице `products` (поле `stock`) в Neon и переживают рестарты.

## Каталог списком и быстрый заказ
- **Список вместо сетки.** Каждая позиция — компактная строка: квадратная миниатюра слева; название, бренд (подкатегория),
  артикул (поле `sku`/`article`/`code` в `products.json`, если заполнено), цена «180,00 ₽/шт» и остаток «В наличии: N шт.» по центру;
  квадратная кнопка `+` справа. Строка остатка показывается, если у товара задан `stock` (в админке).
- **Быстрый заказ в 1 клик.** `+` кладёт 1 шт. в корзину без открытия карточки: вибрация (Telegram Haptic / `navigator.vibrate`),
  всплывающее «+1», счётчик на кнопке и в шапке. Лимит остатка соблюдается. При `stock = 0` кнопка серая «Нет» и заблокирована.
  Если у товара несколько вариантов (`sizes` больше одного), `+` откроет карточку для выбора.
- **Категории** (жидкости, снюс, поды и т. д.) — вкладки над списком, переносятся на несколько строк.

## Обработка заказов (Принять / Отклонить)
Новый заказ приходит админам в Telegram с кнопками **✅ Принять** и **❌ Отклонить**.
- Пока заказ в статусе «в обработке» (`new`/`contacted`), **товар со склада не списывается** . Наличие проверяется при оформлении и ещё раз при «Принять»:
  если товара уже не хватает, бот покажет ошибку, а заказ останется в обработке.
- «Принять» → статус `accepted`: остатки списываются, клиенту уходит сообщение.
- «Отклонить» → статус `rejected`: склад не трогается, клиенту уходит сообщение.
- В профиле клиента статус виден как «В обработке» / «Принят» / «Отклонён» (а также «Выполнен», «Отменён»).
- В админ-панели статус можно менять вручную — склад подстраивается сам (принят/выполнен = списано, отклонён/отменён = возвращено).
- Заказы, оформленные до этого обновления, уже имеют списанные остатки: кнопка «Принять» для них только меняет статус.
